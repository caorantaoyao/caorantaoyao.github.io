AI Infra 系统基础学习手册

使用方式：以对话学习为主。每次选择一个知识点提问，按照“直觉解释 → 底层原理 → 代码例子 → AI Infra 场景 → 小练习”完成一课；本文档负责保存学习顺序、核心结论与复习检查项。

适用方向：AI Infra、训练基础设施、推理基础设施、模型服务与调度。

建议周期：8 周系统基础，每周 10～15 小时。

推荐语言：Python 用于模型和服务实验，C/C++ 用于理解内存、并发与性能；所有关键实验最终在 Linux 环境验证。

最近更新：2026-08-25。

1 学习目标

AI Infra 的系统基础不是背诵操作系统名词，也不是提前学习大量 Kubernetes 配置。学习完成后，应当能够回答四类问题：资源在哪里消耗，程序为什么变慢，系统会怎样失败，以及如何观测和恢复。

每个主题都以可验证的实验结束。只“运行成功”不算掌握；至少还要观察 CPU、内存、磁盘或网络指标，制造一次异常，并解释结果。

4 学习方法

每个知识点都采用同一条闭环：

  1. 理解它向上提供的抽象。
  2. 写一个最小可运行程序。
  3. 观察 CPU、内存、I/O 或网络行为。
  4. 人为制造阻塞、超时、崩溃或资源不足。
  5. 定位原因，记录基线、修改和实验结论。

例如学习线程池时，不能停在“成功处理了请求”。还要回答：线程数从 1 增加到 32 后吞吐如何变化，队列满了怎样处理，一个任务卡住会影响哪些请求，以及为什么 P99 可能突然升高。

5 第一课：Python 程序从命令行启动后发生了什么

5.1 核心结论

操作系统不会直接理解并执行 Python 源代码。对于命令 python app.py，操作系统启动的是 Python 解释器；随后由解释器读取、编译并执行 app.py。

键盘输入
  ↓
终端把字符交给 Shell
  ↓
Shell 解析命令并查找 python
  ↓
创建子进程
  ↓
execve() 加载 Python 解释器
  ↓
CPython 读取 app.py
  ↓
编译成字节码并执行
  ↓
通过系统调用访问文件、网络和终端
  ↓
程序退出，Shell 回收进程

5.2 Shell 解析命令

终端负责接收键盘字符，真正解析命令的是 Shell，例如 bash 或 zsh。Shell 会拆分参数、展开变量和通配符、处理管道与重定向，并根据 PATH 查找 Python 可执行文件。

python app.py --port 8000

它形成的参数数组可以理解为：

argv[0] = "python"
argv[1] = "app.py"
argv[2] = "--port"
argv[3] = "8000"

PATH 查找主要由 Shell 或运行库完成；内核的 execve() 接口最终接收的是一个明确路径。

5.3 创建子进程并加载解释器

传统 Unix 流程通常是 Shell 调用 fork() 创建子进程，子进程调用 execve() 加载 Python，父进程则调用 wait() 等待程序结束。现代系统也可能通过 posix_spawn() 完成更高效的组合操作。

fork() 的作用。创建一个新进程。子进程继承当前工作目录、环境变量、文件描述符、用户身份和权限。内存通常使用写时复制，父子进程最初可以共享相同物理页面，直到其中一方修改。

execve() 的作用。它不会再创建一个进程，而是把当前进程的程序和虚拟地址空间替换为新的可执行程序。因此子进程执行 Python 后，PID 通常保持不变。

如果执行 python app.py > output.log，Shell 会在加载 Python 前让文件描述符 1 指向日志文件。Python 只向文件描述符 1 写数据，并不需要理解 Shell 的重定向语法。

5.5 内核建立虚拟地址空间

子进程调用 execve() 后，内核检查文件与执行权限，识别 Linux ELF 等可执行文件格式，建立新的虚拟地址空间，映射 Python 的代码、数据和共享库，并准备栈、堆、参数及环境变量。动态链接器还会加载 libc 等依赖库。

高地址
┌──────────────┐
│ 栈           │  参数、环境变量、函数调用
├──────────────┤
│ 共享库       │  libc 等
├──────────────┤
│ mmap 区域    │
├──────────────┤
│ 堆           │  动态分配对象
├──────────────┤
│ 数据段       │
├──────────────┤
│ Python 代码  │
└──────────────┘
低地址

这些内容不一定立即进入物理内存。许多页面会在第一次访问时触发 Page Fault，再由内核建立映射或加载数据。

5.6 CPython 执行 app.py

从这里开始主要是用户态中的 CPython 工作。它初始化运行时、内存分配器和导入系统，打开并读取 app.py，将源代码解析为抽象语法树，再编译为 Python 字节码并执行。

if __name__ == "__main__":
    main()

Python 字节码仍然不是 CPU 机器指令。真正由 CPU 执行的是已经编译成机器指令的 CPython 解释器；解释器不断读取和处理 Python 字节码。

5.7 用户态与内核态的切换

普通计算主要发生在用户态。打开文件、创建线程、建立网络连接、等待数据、获取时间或者向终端输出时，程序需要通过系统调用请求内核。

例如 print("hello") 的内容经过 Python 缓冲后，最终通常会形成类似 write(1, "hello\n", 6) 的系统调用。CPU 从用户态进入内核态，内核将数据交给终端、文件或管道，然后再返回用户态。

进程也不会一直独占 CPU。内核调度器为它分配时间片，必要时保存寄存器等状态并切换到其他线程或进程，这就是上下文切换。如果进程正在等待磁盘或网络，内核可以让它睡眠，把 CPU 交给其他任务。

5.8 程序退出

正常结束时，Python 刷新缓冲区并执行必要清理，然后调用退出系统调用。内核关闭文件描述符、释放进程资源并保留退出状态，通知父进程。Shell 通过 wait() 回收该进程，更新退出码并重新显示命令提示符。

如果发生未捕获的 Python 异常，CPython 通常向文件描述符 2 输出 Traceback，并以非零状态码退出。严重的原生代码错误或外部信号则可能让进程直接异常终止。

5.9 三个必须区分的概念

概念

含义

程序

磁盘上的代码和数据，例如 Python 解释器文件

进程

程序的一次运行实例，包含 PID、虚拟地址空间、文件描述符和其他资源

线程

进程内部被 CPU 调度执行的一条执行流
