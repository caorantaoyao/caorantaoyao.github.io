Agent 工具调用：从 Function Calling 到安全执行

一句话理解：模型负责决定“调用哪个工具、传什么参数”，Agent 程序负责校验、鉴权和真正执行，再把结果交回模型。

工具调用（Tool Calling / Function Calling）让大模型能够读取实时数据、访问数据库、操作业务系统和执行外部动作。它是 Agent 区别于普通聊天机器人的核心能力之一。

1. 为什么需要工具调用

模型只能根据当前上下文生成内容，并不知道数据库中的最新订单、Redis 中的状态、用户的飞书日程或服务器上的文件。遇到需要外部信息或实际操作的任务时，模型必须通过工具与外部世界交互。

用户：查询订单 20260729001 的状态
        ↓
模型决定调用 query_order
        ↓
Agent 程序验证参数与权限
        ↓
Python 工具查询数据库
        ↓
工具返回 status=shipped
        ↓
模型回答：订单已经发货

2. 最重要的边界：模型不会真正执行函数

模型生成的是结构化“调用建议”，例如：

{
  "name": "get_weather",
  "arguments": {
    "city": "北京"
  }
}

真正执行 get_weather(city="北京") 的是你的 Python 程序。程序有权拒绝、修改、延迟或要求人工批准，不能因为模型提出调用就盲目执行。

安全原则：模型输出是不可信输入。工具名、参数、身份、租户、权限和风险等级都必须由确定性程序检查。

3. 工具调用的完整流程

  1. 用户向 Agent 提出目标。
  2. Agent 将消息、系统指令和工具说明交给模型。
  3. 模型选择工具并生成结构化参数。
  4. Agent 校验工具是否存在、参数是否合法。
  5. Agent 完成身份鉴别、权限检查和风险判断。
  6. Python 程序执行函数、HTTP、RPC、SQL 或 MCP 调用。
  7. 程序把工具结果与 tool_call_id 一起交回模型。
  8. 模型根据结果继续调用工具或生成最终回答。

5. 工具定义与真实函数的区别

def get_weather(city: str) -> dict:
    return {
        "city": city,
        "temperature": 31,
        "condition": "多云",
    }
weather_tool = {
    "name": "get_weather",
    "description": "查询指定城市当前的天气情况",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {
                "type": "string",
                "description": "需要查询天气的城市名称",
            }
        },
        "required": ["city"],
        "additionalProperties": False,
    },
}

模型看到 Schema 并生成参数；运行时根据工具名称找到对应 Python 函数并执行。

6. 使用 Pydantic 校验模型参数

from pydantic import BaseModel, ConfigDict, Field


class WeatherArguments(BaseModel):
    model_config = ConfigDict(extra="forbid")

    city: str = Field(
        min_length=1,
        max_length=50,
        description="城市名称",
    )


raw_arguments = {"city": "北京"}
arguments = WeatherArguments.model_validate(raw_arguments)
result = get_weather(**arguments.model_dump())

extra="forbid" 可以拒绝模型生成的多余字段。参数格式通过校验只代表“结构合法”，仍需继续判断业务语义和权限。

7. 工具注册表与统一执行器

from collections.abc import Callable
from pydantic import BaseModel


class ToolDefinition:
    def __init__(
        self,
        argument_model: type[BaseModel],
        handler: Callable[..., dict],
    ):
        self.argument_model = argument_model
        self.handler = handler


TOOLS = {
    "get_weather": ToolDefinition(
        argument_model=WeatherArguments,
        handler=get_weather,
    ),
}


def execute_tool(name: str, raw_arguments: dict) -> dict:
    tool = TOOLS.get(name)

    if tool is None:
        return {
            "ok": False,
            "error": {
                "code": "TOOL_NOT_FOUND",
                "retryable": False,
            },
        }

    try:
        arguments = tool.argument_model.model_validate(raw_arguments)
        output = tool.handler(**arguments.model_dump())
        return {"ok": True, "data": output}
    except ValueError as exc:
        return {
            "ok": False,
            "error": {
                "code": "INVALID_ARGUMENTS",
                "message": str(exc),
                "retryable": False,
            },
        }
    except TimeoutError:
        return {
            "ok": False,
            "error": {
                "code": "TOOL_TIMEOUT",
                "retryable": True,
            },
        }

真实系统还应在执行前加入认证上下文、权限判断、审批策略、Deadline、幂等键和审计日志。

8. Agent Loop 如何处理工具调用

MAX_STEPS = 10
messages = [{"role": "user", "content": "查询北京天气"}]

for step in range(MAX_STEPS):
    response = call_model(
        messages=messages,
        tools=get_tool_schemas(),
    )

    if response.has_final_answer:
        final_answer = response.final_answer
        break

    messages.append(response.assistant_message)

    for tool_call in response.tool_calls:
        result = execute_tool(
            name=tool_call.name,
            raw_arguments=tool_call.arguments,
        )

        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": result,
        })
else:
    raise RuntimeError("Agent 超过最大执行步数")

核心循环是：模型提出工具调用，程序执行并写回结果，模型根据观察结果决定下一步。tool_call_id 用来关联工具请求和对应结果。

9. 一个任务可以连续调用多个工具

例如用户要求：“查询订单状态，如果已经发货，就给我发送通知。”

query_order(order_id)
        ↓ status=shipped
send_notification(message)
        ↓ success
模型生成最终回答

第二次调用不是程序预先写死的，而是模型根据第一次工具结果动态决定的。这就是 Agent 相比单次 LLM 请求更强的地方，同时也带来了循环、费用和安全风险。

11. 如何设计高质量工具

  • 名称具体：使用 search_documents、get_order，而不是 process 或 tool_1。
  • 职责单一：查询、创建、取消和退款应有清晰边界。
  • 参数明确：通过类型、枚举、长度和数值范围减少歧义。
  • 返回结构化：统一 ok、data、error.code 和 retryable。
  • 控制结果大小：分页、裁剪、摘要，只返回必要字段。
  • 工具边界不重叠：否则模型难以稳定选择。
  • 描述包含限制：明确何时不应该使用工具。

如果工具只返回“执行失败”，模型无法判断是应该修改参数、重新调用、换工具还是转交人工。

13. 多租户与权限边界

模型可能生成：

{
  "name": "query_documents",
  "arguments": {
    "tenant_id": "company-b",
    "query": "财务数据"
  }
}

如果当前用户属于 company-a，不能按照模型参数访问 company-b。可信身份必须来自服务端认证上下文：

def query_documents(arguments, context):
    trusted_tenant_id = context.tenant_id

    authorize(
        user_id=context.user_id,
        tenant_id=trusted_tenant_id,
        action="document:read",
    )

    return repository.search(
        tenant_id=trusted_tenant_id,
        query=arguments.query,
    )

身份、tenant_id、角色、权限和配额来自 JWT、Session 或服务端上下文，不能由模型自由提供。Casbin/RBAC 可用于判断调用者能否执行某项工具能力。

14. 写操作必须考虑幂等

Agent 调用 create_task 成功，但响应在网络中丢失；如果自动重试，可能创建两个相同任务。解决办法是给同一次逻辑操作使用稳定的幂等键。

def create_task(title: str, idempotency_key: str):
    existing = repository.find_by_idempotency_key(
        idempotency_key
    )

    if existing:
        return existing

    return repository.create(
        title=title,
        idempotency_key=idempotency_key,
    )

工具调用决定“调用什么”；HTTP/RPC 决定“如何调用远程服务”；幂等保证“超时重试不会重复产生副作用”。

16. 工具调用、API、RPC 与 MCP 的关系

用户目标
  ↓
模型生成 Function Call
  ↓
Agent Runtime 校验、鉴权、审批
  ↓
Python 工具函数
  ↓
HTTP / RPC / SQL / Redis / MCP
  ↓
外部系统
  • Function Calling：模型如何表达“我要调用某个工具”。
  • Python 工具函数：Agent 程序中的执行适配层。
  • HTTP/RPC：程序之间如何传输请求。
  • MCP：外部工具和上下文如何被统一发现、描述与调用。
  • Casbin/RBAC：调用者是否有权使用某项工具。

17. 生产环境常见错误

  • 模型返回什么就直接执行，没有参数校验和鉴权。
  • 把 tenant_id、user_id 和角色交给模型决定。
  • 工具返回大量原始数据，浪费上下文并泄露敏感字段。
  • 所有失败都返回普通字符串，没有稳定错误码。
  • 写操作自动重试，却没有幂等键。
  • 没有最大步骤数、Deadline、费用预算和取消机制。
  • 高风险工具没有操作预览与人工审批。
  • 工具名称和职责重叠，导致模型频繁选错。
  • 日志记录完整参数、Token 或敏感数据，没有脱敏。

19. 面试回答模板

工具调用是指模型根据用户目标，从程序提供的工具集合中选择工具并生成结构化参数。模型本身不执行函数，Agent 运行时需要验证工具名称与参数，完成鉴权、风险判断和人工确认，然后调用真实的 Python 函数、HTTP API、RPC 或数据库，再将工具结果与原 tool_call_id 一起返回模型，使模型决定下一步或生成最终回答。生产环境还必须处理超时、有限重试、幂等、租户隔离、结果截断、审计和最大执行步数。

20. 一句话总结

模型负责提出工具调用，程序负责验证和执行，工具结果再驱动模型决定下一步。
