DNS：输入域名后，怎样得到目标 IP

DNS 的核心作用是把人容易记住的域名转换成计算机网络使用的 IP 地址。例如 www.example.com → 203.0.113.10。获得目标 IP 后，计算机才能查询路由表，通过网关和路由器把数据送到目标服务器。

1. 为什么需要 DNS

网络层真正使用 IP 地址定位计算机，但 IP 地址不方便记忆，也可能随服务器迁移或扩容发生变化。域名为服务提供相对稳定、可读的名称，DNS 则维护域名与 IP 等信息之间的映射。它类似通讯录：域名相当于联系人姓名，IP 地址相当于电话号码。

2. DNS 在一次网络请求中的位置

当用户输入 https://www.example.com/index.html 时，浏览器可以解析出协议 HTTPS、域名 www.example.com、默认端口 443 和路径 /index.html。此时虽然已经知道端口，但还不知道服务器 IP，所以必须先进行 DNS 查询。

输入 URL
→ 提取域名
→ DNS 查询
→ 获得目标 IP
→ 查询路由表
→ 通过网关和路由器到达服务器
→ 建立 TCP 或 QUIC 连接
→ 发送 HTTP 请求

DNS 只解决“域名对应哪个 IP”，不负责把网页数据送到该 IP。后续传输由 IP、路由、TCP、UDP或QUIC等协议完成。

3. 查询首先经过多级缓存

如果每次访问网站都从全球 DNS 系统重新查询，延迟和服务器压力都会很大，因此浏览器和操作系统会优先使用缓存。常见检查顺序可以概括为：

浏览器 DNS 缓存
→ 操作系统 DNS 缓存
→ hosts 文件
→ 递归 DNS 服务器
→ DNS 全球层级系统

只要某一级找到仍然有效的结果，就可以直接返回，不再继续向后查询。具体顺序可能因浏览器、操作系统和网络配置而略有差异。

4. hosts 文件是什么

hosts 是操作系统中的本地域名映射文件，可以手动配置 127.0.0.1 localhost 或 192.168.1.20 test.example.com。它常用于本地开发、测试新服务器和临时覆盖 DNS 结果。hosts 文件不是全球 DNS 的一部分，修改它通常只影响当前计算机。

5. 递归 DNS 服务器是什么

本机没有答案时，会向配置的递归 DNS 服务器发送查询。它也常被称为 DNS Resolver、本地 DNS 或公共 DNS，可能由家用路由器、运营商、企业网络、云服务商或公共 DNS 服务提供。

客户端只需要提出“www.example.com 的 IP 是多少”，递归 DNS 负责查找最终答案。这里的“本地 DNS”不一定运行在本机，而是指客户端直接使用的 DNS 查询入口。

6. DNS 为什么使用分层结构

全球域名数量巨大，不可能由一台服务器保存和处理所有记录。DNS 因此按域名层级分工：

.
└── com
    └── example
        └── www

从右向左看，. 是 DNS 根，com 是顶级域，example 是注册域名，www 是其子域名或主机名。日常书写通常省略最后的根点。

7. 根 DNS、顶级域 DNS 与权威 DNS

递归 DNS 没有缓存时，通常会依次询问三类服务器。

根 DNS。根服务器一般不直接返回最终 IP，而是告诉递归 DNS 应该去询问对应的顶级域服务器，例如 .com。

顶级域 DNS。.com 服务器通常告诉递归 DNS，哪个权威 DNS 负责 example.com。

权威 DNS。权威服务器保存该域名实际配置的 DNS 记录，最终返回 A、AAAA、CNAME 等结果。

客户端：www.example.com 的 IP？
→ 递归 DNS
→ 根 DNS：去问 .com
→ .com DNS：去问 example.com 的权威 DNS
→ 权威 DNS：IP 是 203.0.113.10
→ 递归 DNS 返回给客户端

8. 递归查询和迭代查询

递归查询强调“请帮我找到最终答案”。客户端通常向递归 DNS 发起这种查询，不需要自己访问根、顶级域和权威 DNS。

迭代查询强调“如果没有最终答案，就告诉我下一步问谁”。递归 DNS 向 DNS 层级系统查询时，根 DNS 和顶级域 DNS 经常返回下一站信息。

可以整体理解为：客户端向递归 DNS 发起递归查询，递归 DNS 再通过多次查询寻找权威答案。

9. DNS 缓存与 TTL

DNS 查询结果通常带有 TTL，表示记录可以缓存多久。例如 TTL 为 300 秒时，缓存方在有效期内可以直接使用已有结果；到期后需要重新查询。缓存能够降低延迟和服务器压力，但也意味着 DNS 配置变更不会瞬间被所有用户看到。

名称

作用

DNS TTL

决定 DNS 记录可以缓存多久

IP TTL

防止 IP 数据包在网络中无限循环

二者名称相同但作用完全不同。

普通网站访问最常接触 A、AAAA 和 CNAME。

11. CNAME 是怎样工作的

CNAME 让一个域名先指向另一个域名，再继续查询后者的地址。例如：

www.example.com
→ CNAME：web.cdn-provider.com
→ A：203.0.113.10

CNAME 常用于接入 CDN、云服务或统一管理服务入口。它把业务域名与具体服务器地址解耦，但 Resolver 仍需继续解析，最终得到可使用的 IP 地址。

12. 一个域名为什么可以对应多个 IP

权威 DNS 可以为同一域名返回多个 IP，用于分散访问压力、故障切换、跨机房部署、就近访问和 CDN 调度。客户端再根据系统与应用策略选择其中一个地址。

www.example.com
├── 203.0.113.10
├── 203.0.113.11
└── 203.0.113.12

因此，域名和 IP 并非一一对应：一个域名可以对应多个 IP，多个域名也可以共享同一个 IP。

13. DNS 使用 UDP 还是 TCP

传统 DNS 查询通常优先使用 UDP 53 端口，因为普通请求和响应较小，无需建立 TCP 连接。在响应过大或被截断、区域传送以及某些特定协议场景中，DNS 也会使用 TCP。

现代 DNS 还可以通过加密协议传输，例如 DoT（DNS over TLS）、DoH（DNS over HTTPS）和 DoQ（DNS over QUIC）。所以“DNS 只使用 UDP”并不准确。

14. DNS 查询失败会发生什么

DNS 查询可能因为域名不存在、DNS 服务器不可用、网络无法到达 DNS 服务器、缓存错误、权威 DNS 配置错误或域名解析到不可访问的 IP 而失败。此时可能出现“通过 IP 可以访问，但通过域名不能访问”，说明问题可能位于 DNS，而不一定是应用服务器故障。

15. DNS 与负载均衡

DNS 可以通过返回多个 IP 实现初步的流量分配，但它有明显局限：客户端和递归 DNS 会缓存结果，切换不会立即生效；DNS 也不一定掌握服务器的实时负载；已经建立的连接不会因为 DNS 记录变化而自动迁移。

大型系统通常组合使用 DNS → CDN 或负载均衡器 → 应用服务器，让 DNS 负责入口选择，再由后续系统进行更细粒度的流量调度。

16. 从输入网址到找到目标服务的完整过程

  1. 浏览器从 URL 中提取域名。
  2. 检查浏览器缓存、操作系统缓存和 hosts 文件。
  3. 没有结果时，向递归 DNS 服务器查询。
  4. 递归 DNS 先检查自己的缓存。
  5. 没有缓存时，依次寻找根 DNS、顶级域 DNS和权威 DNS提供的答案。
  6. 权威 DNS 返回 A、AAAA 或 CNAME 等记录。
  7. 递归 DNS 按 TTL 缓存结果，并向客户端返回目标 IP。
  8. 客户端根据目标 IP 查询路由表，通过网关和路由器到达服务器。
  9. 目标计算机根据端口把数据交给对应进程。
  10. 浏览器与服务器继续进行 TCP或QUIC、TLS和HTTP通信。
URL
→ 域名
→ DNS
→ IP
→ 路由
→ 目标计算机
→ 端口
→ 目标进程
→ HTTP 服务

17. 常见误区

  • DNS 负责传输网页数据：错误。DNS 只帮助获得目标 IP。
  • 域名永远对应同一个 IP：错误。IP 可以变化，一个域名也可以对应多个 IP。
  • 每次访问都会查询根 DNS：错误。多级缓存可能直接返回结果。
  • 本地 DNS 一定运行在本机：错误。它通常是客户端直接使用的递归 DNS 服务。
  • DNS 只使用 UDP：错误。它也会使用 TCP以及DoH、DoT、DoQ等方式。
  • DNS TTL 等于 IP TTL：错误。前者控制缓存时间，后者限制数据包转发跳数。

18. 面试回答

用户输入域名后，浏览器会先检查自身 DNS 缓存，然后通过操作系统检查系统缓存和 hosts 文件。如果仍然没有结果，操作系统会向配置的递归 DNS 服务器发送查询。递归 DNS 先检查自己的缓存；没有缓存时，会依次询问根 DNS、顶级域 DNS和域名的权威 DNS，最终获得 A、AAAA 或 CNAME 等记录。递归 DNS 按照记录的 TTL 缓存结果，并将目标 IP 返回给客户端。客户端获得 IP 后，才会查询路由表，通过网关和路由器到达目标服务器，最后根据端口找到对应进程。

19. 一句话总结

DNS 把域名转换成目标 IP；得到 IP 后，路由系统才能把数据送到目标计算机。
