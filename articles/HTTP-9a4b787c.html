HTTP：客户端和服务器如何约定请求与响应

HTTP 的核心作用是规定客户端怎样描述请求，以及服务器怎样返回响应。浏览器可以用它表达“请把某个资源发给我”，服务器则返回处理结果和资源内容。HTTP 不仅传输 HTML，也能传输 JSON、图片、视频和文件。

1. HTTP 位于网络分层的哪里

HTTP 是应用层协议，通常建立在 TCP 或 QUIC 提供的传输能力之上。HTTP 负责请求和响应的格式与语义；DNS负责把域名解析成IP，IP与路由负责找到服务器，TCP或QUIC负责传输，TLS负责加密和身份认证。

应用层：HTTP
安全层：TLS
传输层：TCP 或 QUIC
网络层：IP
链路层：以太网、Wi-Fi

常见组合是 HTTP/1.1 → TCP、HTTP/2 → TCP、HTTP/3 → QUIC → UDP。HTTPS 可以总体理解为受 TLS 保护的 HTTP。

2. 请求—响应模型

HTTP 通常由客户端主动发起请求，服务器处理后返回响应。这是最基本的 Request—Response 模型。服务器一般不会无缘无故返回一个普通 HTTP 响应，而是先收到对应请求；WebSocket 等实时机制则是在 HTTP 建连基础上的进一步扩展。

客户端发送 HTTP 请求
→ 服务器处理请求
→ 服务器返回 HTTP 响应

4. HTTP 请求由什么组成

一个 HTTP/1.1 请求可以抽象为请求行、请求头、空行和可选请求体。

POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer abc123
Content-Length: 25

{"name":"Alice","age":20}

请求行包含方法、请求目标和 HTTP 版本；请求头描述域名、数据格式、认证凭证等元数据；空行分隔头部与正文；请求体承载客户端提交的数据。普通 GET 请求通常不需要请求体。

5. HTTP 响应由什么组成

响应可以抽象为状态行、响应头、空行和可选响应体。

HTTP/1.1 201 Created
Content-Type: application/json
Content-Length: 25

{"id":101,"name":"Alice"}

状态行给出协议版本和处理结果；响应头描述内容格式、缓存等元数据；响应体则是真正返回的 HTML、JSON、图片、文件或错误信息。

7. 安全性与幂等性

安全方法按语义不应修改服务器资源，例如 GET、HEAD 和 OPTIONS。这里的“安全”不是指加密。幂等表示同一请求执行一次或多次，预期产生的最终业务状态相同。

10. Content-Type 为什么重要

HTTP 可以传输多种格式，接收方需要根据 Content-Type 解释正文。常见值包括 text/html、application/json、text/plain、image/png、multipart/form-data 和 application/octet-stream。

Accept: application/json 表示客户端希望收到 JSON；Content-Type: application/json 表示当前发送的正文实际是 JSON。

11. HTTP 为什么是无状态协议

无状态表示每个请求在协议语义上相对独立，服务器不能仅凭一个新请求自动知道它与之前请求属于同一用户。系统通常通过 Cookie、Session、Token 或 JWT 维持业务会话。

服务器登录响应：
Set-Cookie: session_id=abc123

浏览器后续请求：
Cookie: session_id=abc123

服务器可以根据 session_id 在数据库或 Redis 中找到登录状态。无状态不代表服务器不能保存数据，而是 HTTP 协议不会自动维护业务会话。

12. HTTP 无状态与 TCP 有连接并不矛盾

TCP 有连接描述传输层维护序列号、确认和重传等状态；HTTP 无状态描述应用层默认不理解请求之间的业务关系。底层完全可以复用同一条 TCP 连接，同时处理多个相互独立的 HTTP 请求。

13. HTTP 长连接

HTTP/1.1 默认支持持久连接，可以在一条 TCP 连接上依次完成多个请求，减少反复握手的成本。这通常称为 Keep-Alive。

建立一条 TCP 连接
→ 请求 HTML
→ 请求 CSS
→ 请求图片
→ 继续复用连接

长连接不等于永久连接。客户端、服务器、代理或负载均衡器都可能因空闲超时、达到请求上限或网络异常关闭连接；它也不等同于 WebSocket 的全双工通信。

14. 一个网页通常包含多个请求

浏览器先请求 HTML，解析后还可能继续请求 CSS、JavaScript、图片和后端 API。因此打开一个网页通常会产生多个 HTTP 请求。缓存、并发连接、连接复用、HTTP/2 多路复用和 CDN 都会影响加载速度。

/index.html
/style.css
/app.js
/logo.png
/api/user
/api/products

HTTP/2 在一条 TCP 连接上并发传输多个流，但底层 TCP 丢包时多个流仍可能一起等待恢复。HTTP/3 基于 QUIC，各流之间的丢包恢复更加独立，并将 TLS 1.3 集成进 QUIC 握手。版本演进改变了传输组织方式，但方法、状态码和资源语义等核心概念仍然延续。

16. HTTP 与 HTTPS

HTTP 明文传输时，中间设备可能读取或篡改内容。HTTPS 通过 TLS 提供加密、完整性保护和服务器身份认证。对于 HTTP/1.1 和 HTTP/2，可以理解为 HTTP → TLS → TCP → IP；对于 HTTP/3，可以理解为 HTTP/3 → QUIC（集成 TLS 1.3）→ UDP → IP。

HTTPS 保护通信链路，但不表示网站业务本身没有越权、SQL注入或代码漏洞。

17. Python 客户端示例

使用 requests 发送 GET 请求：

import requests

response = requests.get(
    "https://api.example.com/users/123",
    params={"lang": "zh"},
    timeout=5,
)

print(response.status_code)
print(response.headers)
print(response.json())

使用 json= 发送 JSON POST 请求时，requests 通常会序列化字典、设置 Content-Type: application/json 并把 JSON 放入请求体。

response = requests.post(
    "https://api.example.com/users",
    json={"name": "Alice", "age": 20},
    timeout=5,
)

18. Python 服务端示例

from fastapi import FastAPI

app = FastAPI()

@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"id": user_id, "name": "Alice"}

@app.post("/users", status_code=201)
def create_user(user: dict):
    return {"id": 101, **user}

当客户端请求 GET /users/123 时，FastAPI 根据方法和路径匹配函数，解析路径参数，调用业务代码，把 Python 对象序列化成 JSON，再生成 HTTP 响应。HTTP 负责协议约定，Web 框架负责把协议内容映射到 Python 函数。

19. 一次 HTTP 请求的完整生命周期

  1. 客户端解析 URL。
  2. DNS 将域名解析成 IP。
  3. 操作系统查询路由表，数据通过网关和路由器到达服务器。
  4. HTTP/1.1或HTTP/2建立TCP连接，HTTP/3建立QUIC连接。
  5. HTTPS完成TLS安全握手。
  6. 客户端发送HTTP请求。
  7. 负载均衡器或反向代理接收并转发请求。
  8. Python Web框架匹配路由并调用业务代码。
  9. 业务代码访问缓存、数据库或其他服务。
  10. 服务器生成HTTP响应并沿网络返回客户端。
URL
→ DNS
→ IP 与路由
→ TCP/QUIC
→ TLS
→ HTTP 请求
→ 服务端业务处理
→ HTTP 响应

20. 常见误区

  • HTTP 负责寻找服务器：错误。DNS负责获得IP，IP与路由负责找到服务器。
  • POST一定安全，GET一定不安全：错误。加密取决于HTTPS，业务安全还取决于认证、授权和实现。
  • HTTP无状态等于服务器不能保存状态：错误。服务器可以通过Session、数据库和Redis保存业务状态。
  • HTTP长连接就是WebSocket：错误。前者主要复用底层连接，后者提供全双工通信。
  • 502表示业务代码一定崩溃：错误。它表示网关未从上游得到有效响应，原因需要结合链路排查。
  • HTTPS是一种完全不同的业务协议：错误。它主要是受TLS保护的HTTP。

21. 面试回答

HTTP 是应用层的请求—响应协议，规定客户端怎样描述请求、服务器怎样返回结果。请求通常由请求行、请求头、空行和可选请求体组成；响应由状态行、响应头、空行和可选响应体组成。方法表达资源操作语义，状态码表达处理结果，Header传递格式、认证、缓存等元数据。HTTP本身无状态，业务通常通过Cookie、Session或Token维持用户状态。HTTP/1.1支持持久连接，HTTP/2在TCP连接上提供二进制分帧和多路复用，HTTP/3则基于QUIC。

22. 一句话总结

HTTP 约定客户端如何提出请求、服务器如何返回响应；底层网络负责把消息送达，服务端业务代码负责真正处理请求。
