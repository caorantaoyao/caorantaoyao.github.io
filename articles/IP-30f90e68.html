IP 与路由：数据知道目标端口后，怎样找到目标计算机

只知道目标端口还不足以完成网络通信。IP 地址负责找到目标计算机，端口负责在目标计算机上找到对应进程。例如 203.0.113.10:443 表示：先把数据送到 IP 地址为 203.0.113.10 的计算机，再交给监听 443 端口的进程。

1. IP 地址和端口各自负责什么

一次网络通信通常可以用源 IP、源端口、目标 IP 和目标端口描述。例如 192.168.1.10:52000 → 203.0.113.10:443。IP 地址解决跨网络的主机定位，端口解决主机内部的进程定位，路由器负责在多个网络之间选择下一步路径。

2. 数据发送的整体流程

  1. 应用通过 TCP 或 UDP Socket 提供目标 IP端口等信息。
  2. IP 层加入源 IP 和目标 IP，形成 IP 数据包。
  3. 操作系统查询本机路由表，决定网络接口和下一跳。
  4. 本机在当前局域网内找到下一跳的 MAC 地址并发送数据帧。
  5. 一个或多个路由器根据目标 IP 逐跳转发。
  6. 数据到达目标计算机后，操作系统根据协议和目标端口交给对应 Socket。

→ 根据端口交给目标进程

3. 第一步：判断目标是否在同一局域网

操作系统会结合本机 IP、子网掩码和目标 IP，判断目标是否属于本地网络。假设本机 IP 为 192.168.1.10，子网掩码为 255.255.255.0，默认网关为 192.168.1.1。

目标位于同一局域网。如果目标是 192.168.1.20，双方都属于 192.168.1.0/24。本机可以在局域网内直接把数据发给目标计算机。

目标位于其他网络。如果目标是 203.0.113.10，本机无法在局域网内直接送达，于是先把数据交给默认网关，再由路由器继续转发。

4. 第二步：查询路由表

每台计算机和路由器都有路由表。路由表记录不同目标网络应该从哪个接口发送、交给哪个下一跳。它不是为每台互联网计算机保存一条路线，而是通常按目标网段组织规则。

目标网络

处理方式

192.168.1.0/24

本地网络，直接发送

10.0.0.0/8

交给指定的内部路由器

0.0.0.0/0

其他目标交给默认网关

如果多条路由都能匹配目标 IP，通常选择范围最具体的一条，这叫最长前缀匹配。例如目标 10.10.20.8 同时匹配 10.0.0.0/8、10.10.0.0/16 和 10.10.20.0/24 时，会选择最具体的 10.10.20.0/24。如果没有具体规则匹配，就使用默认路由。

5. 默认网关是什么

默认网关是本机通往其他网络的默认出口，家庭网络中通常就是家用路由器。你的计算机不需要提前知道数据在互联网上经过的完整路线，只要知道第一步应该交给哪个网关即可。

本机只决定自己的下一跳；后续每台路由器再分别决定下一跳。

6. 第三步：找到下一跳的 MAC 地址

IP 地址用于跨网络定位，但以太网或 Wi-Fi 在当前局域网内发送数据时还需要 MAC 地址。IPv4 通常通过 ARP 查询下一跳的 MAC 地址。

谁拥有 192.168.1.1？
请把你的 MAC 地址告诉我。

192.168.1.1：
我的 MAC 是 AA:BB:CC:DD:EE:FF

如果目标就在同一局域网，本机寻找目标计算机的 MAC；如果目标在外网，本机寻找的是默认网关的 MAC，而不是远程服务器的 MAC。MAC 地址只服务于当前一跳，每经过一个路由器，链路层的源 MAC 和目标 MAC 通常都会变化。

7. 第四步：路由器逐跳转发

路由器收到 IP 数据包后，会读取目标 IP、查询自己的路由表、选择下一跳和出口接口，然后继续发送。数据可能依次经过家用路由器、运营商网络、互联网骨干网和目标机房路由器，最终到达服务器所在网络。

你的计算机
→ 家用路由器
→ 运营商路由器
→ 骨干网路由器
→ 目标机房路由器
→ 目标服务器

这叫逐跳转发。中间路由器主要依据目标 IP 进行普通路由，并不负责最终把数据交给具体应用程序。

8. 第五步：目标计算机根据端口找到进程

数据到达目标计算机后，IP 层确认目标 IP 属于本机，再把数据交给 TCP 或 UDP。传输层读取目标端口，并在操作系统维护的 Socket 信息中找到对应程序。例如目标端口为 443 时，数据会交给监听该端口的 Web 服务进程。

目标 IP → 找到目标计算机
目标端口 → 找到目标 Socket
目标 Socket → 找到目标进程

9. 如果应用只知道域名

应用如果只有 www.example.com，通常需要先通过 DNS 得到服务器 IP。DNS 解决“域名对应哪个 IP”，路由解决“数据怎样到达这个 IP”。得到 IP 后，才进入路由表查询和逐跳转发流程。

域名
→ DNS 解析
→ 得到目标 IP
→ 查询路由表
→ 逐跳转发
→ 到达目标计算机
→ 根据端口交给进程

10. NAT 在哪里出现

家庭和企业内部经常使用 192.168.x.x、10.x.x.x 等私有 IP。私有 IP 不能直接作为公网中的全局地址使用，因此出口路由器通常会执行 NAT，把内部源 IP 和端口转换成公网 IP 和新的端口。

192.168.1.10:52000
        ↓ NAT
公网 IP:61000

路由器保存映射关系。服务器响应到达公网 IP 和对应端口后，路由器再根据映射把数据转回内部计算机。因此 NAT 不只是修改 IP，常见的端口地址转换还会同时处理端口。

11. TTL 为什么存在

IP 数据包包含 TTL 字段。每经过一个路由器，TTL 通常减 1；当 TTL 变为 0 时，路由器丢弃该数据包。它可以防止路由配置错误时，数据包在网络中无限循环。traceroute 等工具也会利用 TTL 观察数据经过的路由器。

12. IP 是否保证数据一定到达

IP 提供的是尽力而为的投递，不保证数据一定到达，也不保证顺序、唯一性和固定路线。TCP 可以在 IP 之上提供确认、重传和排序；UDP 本身不提供这些保证，应用或 QUIC 等上层协议可以根据需要补充。

13. 容易混淆的概念

  • 只知道端口就能通信：错误，还需要目标 IP；端口只在目标计算机内部定位进程。
  • 默认网关知道完整路径：错误，每台设备通常只根据当前路由表决定下一跳。
  • 访问外网服务器时需要服务器 MAC：错误，本机只需要当前下一跳，也就是默认网关的 MAC。
  • MAC 地址会像目标 IP 一样端到端不变：错误，MAC 地址通常逐跳变化，目标 IP 通常保持不变。
  • IP 能保证数据送达：错误，可靠性需要由 TCP 或上层协议补充。
  • 路由器根据端口找到服务器进程：错误，普通 IP 路由主要根据目标 IP；端口由终点的传输层处理。

14. 面试回答

应用先通过 TCP 或 UDP Socket 指定目标 IP、目标端口和数据。传输层加入端口信息，IP 层加入源 IP 和目标 IP。操作系统查询路由表，判断目标是否在本地网络：如果在同一局域网，就直接发送；如果不在，就交给默认网关。发送当前一跳之前，还需要通过 ARP 等机制获得下一跳的 MAC 地址。路由器收到数据包后，根据目标 IP 和自己的路由表逐跳转发。数据到达目标计算机后，目标操作系统再根据协议和目标端口，将数据交给对应的 Socket 和应用进程。

15. 一句话总结

IP 地址和路由负责把数据送到目标计算机，端口负责在目标计算机上找到对应进程；每台计算机或路由器通过查询自己的路由表，让数据逐跳接近目标网络。
