RAG 检索与重排

一句话结论

RAG 的检索阶段负责从大规模知识中高召回候选，重排阶段负责用更精细的相关性判断把真正能回答问题的片段放到上下文前部；两者共同决定模型最终能看到什么证据。

前置知识与边界

  • 前置知识：Embedding、向量相似度、关键词检索、Transformer 上下文窗口。
  • 适用范围：答案依赖外部、私有或持续更新的知识。
  • 不解决的问题：检索到正确证据后模型仍可能推理错误；需要生成评测和引用校验兜底。

核心原理与执行流程

典型流程为：查询理解与改写 → 多路召回 → 候选合并与去重 → 重排 → 上下文组装 → 带引用生成。

向量召回擅长语义相近表达，BM25 等关键词召回擅长专有名词、编号和精确词。混合检索先扩大候选覆盖，再使用 Cross-Encoder、LLM 打分或轻量学习排序模型重排。重排要同时考虑相关性、证据完整性、时效性、权限和片段多样性，不能只按单一相似度排序。

工程实现

  • 切分时保留标题、章节、来源、更新时间和权限等元数据。
  • 查询改写保留用户实体和约束，避免语义扩展抹掉精确条件。
  • 多路召回分别设定 top-k，再用 RRF 或归一化分数融合。
  • 重排只处理有限候选，设置超时和降级，防止延迟失控。
  • 上下文组装按 token 预算去重、补邻接片段，并保留稳定引用标识。
  • 记录查询、候选、分数、最终上下文、引用和答案，支持轨迹评测。

故障模式与排查

  1. 没召回正确文档：分别检查查询改写、索引覆盖、切分粒度和各召回通道的 Recall@k。
  2. 正确文档被排到后面：检查重排训练分布、截断、负样本和融合分数。
  3. 上下文包含重复片段：按文档、章节和语义近重复进行去重并控制多样性。
  4. 引用与答案不匹配：验证答案句子是否可由引用片段直接支持，不只检查引用存在。
  5. P99 延迟过高：分解改写、召回、重排、组装和生成各阶段耗时，设置超时降级。

面试问答阶梯

  1. 为什么向量库检索之后还需要重排？
  2. BM25 与向量检索各自擅长什么，如何融合？
  3. chunk 太大或太小分别会发生什么？
  4. 如何构建离线评测集并区分检索失败和生成失败？
  5. 设计一个支持权限、时效性、引用和低延迟的企业 RAG 系统。

验证与实践

  • 最小实验：建立含同义表达、精确编号和干扰文档的小语料，对比向量、BM25、混合和重排结果。
  • 关键指标：Recall@k、MRR、nDCG、上下文精确率、引用支持率、端到端正确率与 P95/P99 延迟。
  • 项目应用：保存每次查询的候选轨迹，建立“检索错误 / 重排错误 / 生成错误”三级失败归因。
  • 延伸方向：Query Routing、HyDE、Multi-Query、RRF、ColBERT、Contextual Retrieval 和权限过滤。
