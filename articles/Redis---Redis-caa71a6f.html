Redis 入门：为什么需要 Redis

一句话结论：Redis 是一个独立运行的内存数据存储服务。它不是为了替代 PostgreSQL，而是负责缓存、短期状态、任务队列、计数、限流和跨进程协调。

一、Redis 到底是什么

Redis 的全称可以理解为 Remote Dictionary Server，即“远程字典服务器”。它以独立服务进程运行，主要使用服务器内存保存数据，其他程序通过网络连接它。

Redis 不是一块独立的物理内存。假设服务器有 8 GB 内存，操作系统、FastAPI、PostgreSQL、Redis 和 Agent 容器都会共同使用这 8 GB；只不过 Redis 有自己的进程、端口、配置和内存上限。

8 GB 服务器内存
├── 操作系统：1.5 GB
├── FastAPI：0.5 GB
├── PostgreSQL：2 GB
├── Redis：1 GB
├── Agent 容器：2 GB
└── 剩余缓冲：1 GB

二、Redis 与 Python 字典的区别

Python 字典只属于当前 Python 进程：

cache = {"user:1001": {"name": "曹然"}}
  • 程序重启后，字典内容通常消失。
  • 其他进程和其他服务器不能直接共享。
  • 没有统一的过期时间、持久化和主从复制能力。

Redis 相当于一个可以被多个服务共同访问的增强型字典服务器：

FastAPI ─────┐
Agent Worker ─┼── Redis
调度器 ──────┘

三、为什么不能只使用 PostgreSQL

PostgreSQL 擅长长期、可靠地保存核心业务数据，也支持复杂查询、约束和事务。但系统中还有大量高频、短期、结构简单的状态，例如验证码、缓存、任务进度和并发计数。

如果 Agent 每秒更新一次执行状态，一百个任务就会不断产生大量短小读写。这些状态可能几分钟后便失去价值，却会持续占用数据库连接和 I/O。

职责划分：PostgreSQL 负责长期正确的数据，Redis 负责快速访问和短期协调。

四、Redis 最经典的用途：缓存

这种模式称为 Cache Aside，也叫旁路缓存：

  1. 先查询 Redis。
  2. 命中时直接返回。
  3. 未命中时查询数据库。
  4. 把结果写入 Redis，并设置过期时间。
  5. 返回查询结果。
import json
import redis.asyncio as redis

cache = redis.Redis(host="localhost", port=6379, decode_responses=True)

async def get_user(user_id: int):
    key = f"user:{user_id}"
    cached = await cache.get(key)
    if cached is not None:
        return json.loads(cached)

    user = await query_user_from_database(user_id)
    await cache.set(key, json.dumps(user), ex=300)
    return user

ex=300 表示这个缓存 300 秒后自动失效。

六、Redis 为什么快

  • 主要数据位于内存，减少磁盘访问。
  • 核心命令和数据结构设计简单。
  • 许多常用操作时间复杂度很低。
  • 单条 Redis 命令通常具有原子性。
  • 网络协议与事件处理经过专门优化。

但 Redis 快不代表容量无限。它明显受服务器内存限制，不能把所有长期数据都无脑放入 Redis。

七、过期时间与短期数据

SET verification:13800000000 9527 EX 300
TTL verification:13800000000

Redis 可以自动删除过期 Key，非常适合验证码、Session、临时 Token、幂等键、限流窗口和 Agent 短期运行状态。

八、Redis 在 AI Agent 平台中的职责

1. 任务队列

服务器只能并发运行少量 Agent，其余任务先进入队列。某个任务完成后，Worker 再领取下一个任务，避免 CPU 和内存被瞬间耗尽。

2. 运行状态

agent:run:1001:status = queued
agent:run:1002:status = running
agent:run:1003:status = succeeded

Redis 适合提供实时状态查询，但最终结果和审计记录仍应写入 PostgreSQL。

3. 并发控制

tenant:1001:running_tasks = 2

任务启动时原子加一，结束时原子减一；达到租户上限后让新任务排队。

4. 限流

按照租户、用户或 API 维护时间窗口计数，防止单个租户耗尽整个平台资源。

5. 分布式锁

多个 Worker 可能同时争抢同一个任务。Redis 锁可以减少重复处理，但必须设置唯一持有者、过期时间和安全释放逻辑，不能简单地随意删除锁 Key。

十、Redis 数据会不会丢失

有可能。Redis 主要使用内存，进程异常或服务器故障可能造成数据丢失。常见持久化机制包括：

  • RDB：定期生成数据快照，文件紧凑、恢复较快，但两次快照之间的数据可能丢失。
  • AOF：记录写命令，通常能缩小数据丢失窗口，但文件和恢复成本可能更高。

Redis 可以同时启用 RDB 与 AOF，但核心业务数据仍不应该只保存在 Redis。

十二、什么时候不需要 Redis

如果项目只有一个 FastAPI 进程、用户量很小、没有后台任务，也没有明显的数据库压力，可以先只使用 PostgreSQL。不要为了技术栈看起来完整而强行增加 Redis。

出现以下需求时再引入更合理：

  • 需要任务队列或后台 Worker。
  • 多个进程需要共享短期状态。
  • 大量重复查询需要缓存。
  • 需要验证码、Session、限流或并发控制。
  • 需要排行榜、高速计数器或分布式锁。

十三、面试回答模板

Redis 是一个以内存为主要存储介质的高性能数据结构服务器，支持 String、Hash、List、Set、Sorted Set 和 Stream 等结构，常用于缓存、Session、计数器、排行榜、限流、分布式锁和任务队列。它一般与关系型数据库配合使用：数据库保存长期权威数据，Redis 处理高频访问和短期协调。同时需要关注持久化、缓存一致性、穿透、击穿、雪崩、大 Key、热 Key 和高可用问题。

十四、针对当前 Agent 平台的结论

PostgreSQL：用户、租户、Agent 配置、任务最终结果、账单和审计日志。

Redis：任务队列、实时运行状态、并发计数、限流、临时锁和短期缓存。
