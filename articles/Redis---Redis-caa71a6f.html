Redis 入门：为什么需要 Redis

一句话结论：Redis 是一个独立运行的内存数据存储服务。它不是为了替代 PostgreSQL，而是负责缓存、短期状态、任务队列、计数、限流和跨进程协调。

一、Redis 到底是什么

Redis 的全称可以理解为 Remote Dictionary Server，即“远程字典服务器”。它以独立服务进程运行，主要使用服务器内存保存数据，其他程序通过网络连接它。

Redis 不是一块独立的物理内存。假设服务器有 8 GB 内存，操作系统、FastAPI、PostgreSQL、Redis 和 Agent 容器都会共同使用这 8 GB；只不过 Redis 有自己的进程、端口、配置和内存上限。

8 GB 服务器内存
├── 操作系统：1.5 GB
├── FastAPI：0.5 GB
├── PostgreSQL：2 GB
├── Redis：1 GB
├── Agent 容器：2 GB
└── 剩余缓冲：1 GB

二、Redis 与 Python 字典的区别

Python 字典只属于当前 Python 进程：

cache = {"user:1001": {"name": "曹然"}}
  • 程序重启后，字典内容通常消失。
  • 其他进程和其他服务器不能直接共享。
  • 没有统一的过期时间、持久化和主从复制能力。

Redis 相当于一个可以被多个服务共同访问的增强型字典服务器：

FastAPI ─────┐
Agent Worker ─┼── Redis
调度器 ──────┘

三、为什么不能只使用 PostgreSQL

PostgreSQL 擅长长期、可靠地保存核心业务数据，也支持复杂查询、约束和事务。但系统中还有大量高频、短期、结构简单的状态，例如验证码、缓存、任务进度和并发计数。

如果 Agent 每秒更新一次执行状态，一百个任务就会不断产生大量短小读写。这些状态可能几分钟后便失去价值，却会持续占用数据库连接和 I/O。

职责划分：PostgreSQL 负责长期正确的数据，Redis 负责快速访问和短期协调。

四、Redis 最经典的用途：缓存

这种模式称为 Cache Aside，也叫旁路缓存：

  1. 先查询 Redis。
  2. 命中时直接返回。
  3. 未命中时查询数据库。
  4. 把结果写入 Redis，并设置过期时间。
  5. 返回查询结果。
import json
import redis.asyncio as redis

cache = redis.Redis(host="localhost", port=6379, decode_responses=True)

async def get_user(user_id: int):
    key = f"user:{user_id}"
    cached = await cache.get(key)
    if cached is not None:
        return json.loads(cached)

    user = await query_user_from_database(user_id)
    await cache.set(key, json.dumps(user), ex=300)
    return user

ex=300 表示这个缓存 300 秒后自动失效。

六、Redis 为什么快

  • 主要数据位于内存，减少磁盘访问。
  • 核心命令和数据结构设计简单。
  • 许多常用操作时间复杂度很低。
  • 单条 Redis 命令通常具有原子性。
  • 网络协议与事件处理经过专门优化。

但 Redis 快不代表容量无限。它明显受服务器内存限制，不能把所有长期数据都无脑放入 Redis。

七、过期时间与短期数据

SET verification:13800000000 9527 EX 300
TTL verification:13800000000

Redis 可以自动删除过期 Key，非常适合验证码、Session、临时 Token、幂等键、限流窗口和 Agent 短期运行状态。

八、Redis 在 AI Agent 平台中的职责

1. 任务队列

服务器只能并发运行少量 Agent，其余任务先进入队列。某个任务完成后，Worker 再领取下一个任务，避免 CPU 和内存被瞬间耗尽。

2. 运行状态

agent:run:1001:status = queued
agent:run:1002:status = running
agent:run:1003:status = succeeded

Redis 适合提供实时状态查询，但最终结果和审计记录仍应写入 PostgreSQL。

3. 并发控制

tenant:1001:running_tasks = 2

任务启动时原子加一，结束时原子减一；达到租户上限后让新任务排队。

4. 限流

按照租户、用户或 API 维护时间窗口计数，防止单个租户耗尽整个平台资源。

5. 分布式锁

多个 Worker 可能同时争抢同一个任务。Redis 锁可以减少重复处理，但必须设置唯一持有者、过期时间和安全释放逻辑，不能简单地随意删除锁 Key。

十、Redis 数据会不会丢失

有可能。Redis 主要使用内存，进程异常或服务器故障可能造成数据丢失。常见持久化机制包括：

  • RDB：定期生成数据快照，文件紧凑、恢复较快，但两次快照之间的数据可能丢失。
  • AOF：记录写命令，通常能缩小数据丢失窗口，但文件和恢复成本可能更高。

Redis 可以同时启用 RDB 与 AOF，但核心业务数据仍不应该只保存在 Redis。

十二、什么时候不需要 Redis

如果项目只有一个 FastAPI 进程、用户量很小、没有后台任务，也没有明显的数据库压力，可以先只使用 PostgreSQL。不要为了技术栈看起来完整而强行增加 Redis。

出现以下需求时再引入更合理：

  • 需要任务队列或后台 Worker。
  • 多个进程需要共享短期状态。
  • 大量重复查询需要缓存。
  • 需要验证码、Session、限流或并发控制。
  • 需要排行榜、高速计数器或分布式锁。

十三、面试回答模板

Redis 是一个以内存为主要存储介质的高性能数据结构服务器，支持 String、Hash、List、Set、Sorted Set 和 Stream 等结构，常用于缓存、Session、计数器、排行榜、限流、分布式锁和任务队列。它一般与关系型数据库配合使用：数据库保存长期权威数据，Redis 处理高频访问和短期协调。同时需要关注持久化、缓存一致性、穿透、击穿、雪崩、大 Key、热 Key 和高可用问题。

十四、针对当前 Agent 平台的结论

PostgreSQL：用户、租户、Agent 配置、任务最终结果、账单和审计日志。

Redis：任务队列、实时运行状态、并发计数、限流、临时锁和短期缓存。

十五、Redis 客户端：每种语言是不是都封装好了

结论：主流编程语言基本都有成熟的 Redis 客户端库。业务代码调用的是客户端库，客户端再通过 Redis 的通信协议与独立运行的 Redis Server 交互。因此，开发者通常不需要自己编写 TCP 通信、命令编码和响应解析。

Python、Java、Go 等业务代码
        ↓ 调用 get、set、hset 等方法
Redis 客户端库
        ↓ 把方法编码成 RESP 命令
TCP 或 TLS 网络连接
        ↓
Redis Server 执行命令并返回结果

例如，Python 中的 redis.set("session:abc", "user_1001", ex=1800) 看起来像普通函数调用，但它并不是访问本地字典。客户端会把它转换成类似 SET session:abc user_1001 EX 1800 的 Redis 命令，通过网络发送给 Redis Server，再把响应转换成 Python 对象。

“都有客户端”不等于“客户端完全相同”。不同库在异步模型、连接池、Cluster、Sentinel、自动重连和维护活跃度方面可能不同。选型时应优先查看是否支持当前 Redis 部署模式，以及是否适配项目的同步或异步执行模型。

2. 客户端库替开发者封装了什么

客户端主要封装连接建立与复用、Redis 命令编码、响应解析、连接池、认证、超时配置，以及部分 Cluster、Sentinel、Pipeline 和事务接口。有了这些封装，开发者可以使用语言原生的数据和异常处理方式，而不需要直接操作 Redis 的 RESP 协议。

但是客户端不能把远程服务变成本地变量。每次 Redis 调用仍可能经历网络延迟、超时、连接中断、服务端过载和返回不确定等问题。连续执行十次 Redis 命令通常意味着多次网络往返；需要时应使用批量命令、MGET 或 Pipeline 减少往返次数。

3. Python 同步调用示例

from redis import Redis

redis_client = Redis(
    host="localhost",
    port=6379,
    decode_responses=True,
    socket_connect_timeout=1,
    socket_timeout=1,
)

redis_client.set("user:1001:name", "小明", ex=3600)
name = redis_client.get("user:1001:name")
print(name)

decode_responses=True 会把返回的字节数据解码成字符串；ex=3600 表示这个 Key 在 3600 秒后过期。客户端通常会维护连接池，因此不应该在每个请求里重新创建一个客户端和一条新连接。

4. FastAPI 异步调用示例

from redis.asyncio import Redis

redis_client = Redis.from_url(
    "redis://localhost:6379/0",
    decode_responses=True,
    socket_connect_timeout=1,
    socket_timeout=1,
    max_connections=100,
)

async def save_session(session_id: str, user_id: str) -> None:
    key = f"session:{session_id}"
    await redis_client.set(key, user_id, ex=1800)

async def get_session(session_id: str) -> str | None:
    return await redis_client.get(f"session:{session_id}")

FastAPI 的异步路由应使用异步 Redis 客户端，否则同步网络调用会阻塞事件循环。通常在应用启动时创建一个共享客户端，在应用关闭时释放连接，而不是每处理一个 HTTP 请求就创建一次。

5. 客户端没有替开发者决定什么

客户端只负责“怎样调用”，不会替业务决定“怎样使用”。开发者仍然需要设计 Key 命名与租户隔离、选择 String 或 Hash 等数据结构、决定 TTL、处理缓存与数据库一致性、限制大 Key 和热 Key，并为 Redis 不可用准备降级策略。

值的序列化也属于业务设计。Redis 保存的本质上是字节数据；字符串可以直接保存，Python 字典等复杂对象通常需要转换成 JSON、MessagePack 等格式。反序列化不可信数据时还要考虑安全问题，不能因为客户端返回了 Python 对象就忽略数据来源。

十六、在项目中使用 Redis 客户端时要注意什么

问题

实践建议

连接

复用长连接和连接池，不要每个请求重新连接 Redis。

超时

显式设置连接超时和命令超时，避免请求无限等待。

TTL

缓存、Session、验证码和幂等键应设置符合业务生命周期的过期时间。

Key 命名

使用可读命名空间，例如 prod:tenant:42:session:abc，避免不同业务互相覆盖。

序列化

明确 JSON 等格式及版本，避免随意保存无法兼容的语言对象。

重试

只对确认安全的操作重试；写操作超时不代表服务端一定没有执行。

降级

提前决定 Redis 不可用时是查询数据库、返回旧值、限流还是快速失败。

容量

限制单个 Value 和集合规模，监控内存、大 Key、热 Key、命中率和延迟。

尤其要注意重试的不确定性。如果客户端发送写命令后超时，服务端可能已经执行成功，只是响应没有及时返回。盲目重试非幂等操作可能造成重复计数、重复入队或重复占用资源。因此，重试策略必须与幂等键、唯一约束或业务去重机制配合。

面试时可以这样概括：Redis 是独立服务，主流语言通过客户端库使用 RESP 协议调用它。客户端封装了连接、命令编码、响应解析和连接池，但数据结构、Key、TTL、一致性、重试、降级和容量治理仍由业务系统负责。
