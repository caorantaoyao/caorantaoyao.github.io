同机进程网络通信：从 Socket、Loopback 到 Unix Domain Socket

1. 核心结论

同一台计算机上的不同进程，可以通过 Socket 与回环网络（Loopback）按照 TCP/IP 协议通信。例如浏览器访问 http://127.0.0.1:8000，浏览器进程是客户端，FastAPI 进程是服务端。

两个进程不会直接访问彼此的内存。客户端把数据交给操作系统内核，内核根据 Socket 和协议状态把数据送入服务端的接收缓冲区。

客户端进程
→ 客户端 Socket
→ 操作系统内核
→ TCP/UDP 协议栈
→ Loopback 回环接口
→ 服务端 Socket
→ 服务端进程

2. 为什么进程不能直接交换数据

现代操作系统通常为每个进程提供独立的虚拟地址空间。进程 A 默认不能读取或修改进程 B 的内存，这保证了隔离性与安全性。进程间通信必须借助操作系统提供的 IPC 机制，例如管道、共享内存、消息队列、信号或 Socket。

Socket 是操作系统内核中的通信端点。进程持有指向 Socket 的文件描述符，并通过 send、recv、read、write 等系统调用与内核交换数据。

3. Loopback 回环地址

IPv4 常用回环地址是 127.0.0.1，对应域名通常是 localhost；IPv6 回环地址是 ::1。向回环地址发送数据，表示目标就是本机。

数据一般不会进入物理网卡、交换机或路由器，而是在本机内核的网络协议栈中完成投递。不过 TCP 的连接、序列号、确认、发送缓冲区、接收缓冲区和关闭状态等语义依然存在。

进程 A 用户态
→ 内核 TCP/IP 协议栈
→ Loopback
→ 内核 TCP/IP 协议栈
→ 进程 B 用户态

4. IP、端口与 Socket 的关系

可以粗略地说，IP 地址定位主机，端口定位主机上的网络服务。但更严谨的表述是：端口绑定在内核 Socket 上，进程通过文件描述符持有这个 Socket。

127.0.0.1:8000
        ↓
内核中的监听 Socket
        ↓
文件描述符
        ↓
FastAPI 进程

收到目标端口为 8000 的连接请求时，内核会查找对应的监听 Socket，再通知持有它的服务端进程。

5. TCP 服务端与客户端如何建立连接

TCP 服务端通常依次执行：

socket()
→ bind()
→ listen()
→ accept()
→ recv()/send()
→ close()

客户端通常执行：

socket()
→ connect(127.0.0.1:8000)
→ send()/recv()
→ close()

bind 把监听 Socket 绑定到本地地址；listen 使其进入监听状态；accept 从已完成连接队列中取出一条连接，并返回新的已连接 Socket。监听 Socket 继续负责接收新连接，已连接 Socket 负责与某个客户端收发数据。

6. 四元组如何区分 TCP 连接

客户端连接服务端时，操作系统通常自动给客户端分配临时端口。例如：

客户端：127.0.0.1:53124
服务端：127.0.0.1:8000

一条 TCP 连接通常由四元组标识：

  • 源 IP
  • 源端口
  • 目标 IP
  • 目标端口

多个客户端可以同时访问相同服务端口，因为它们的四元组不同：

127.0.0.1:53124 → 127.0.0.1:8000
127.0.0.1:53125 → 127.0.0.1:8000
127.0.0.1:53126 → 127.0.0.1:8000

7. 同机 TCP 仍然需要三次握手吗

使用 TCP 时，逻辑上仍然会建立 TCP 连接，包括 SYN、SYN+ACK 和 ACK 三次握手。区别在于报文由同一个内核通过 Loopback 处理，不经过外部网络。

客户端 → SYN
服务端 → SYN + ACK
客户端 → ACK

同机 TCP 仍然可能出现 Connection refused、TIME_WAIT、CLOSE_WAIT、连接超时和缓冲区阻塞等现象，只是通常没有真实物理链路上的传播延迟和丢包。

8. 一次 send 到 recv 的内核路径

  1. 客户端调用 send()，从用户态进入内核态。
  2. 数据进入客户端 Socket 的发送缓冲区。
  3. TCP 层维护序列号、确认和连接状态。
  4. IP 层识别目标为回环地址。
  5. Loopback 把数据交回本机协议栈。
  6. 内核根据四元组找到服务端已连接 Socket。
  7. 数据进入服务端 Socket 的接收缓冲区。
  8. 服务端调用 recv()，数据从内核返回用户态。

因此，即便双方在同一台机器上，仍然存在系统调用、缓冲区管理、用户态与内核态切换，以及可能的数据复制开销。

9. Python TCP 示例

服务端

import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(("127.0.0.1", 8000))
server.listen()

print("监听 127.0.0.1:8000")
connection, client_address = server.accept()

try:
    data = connection.recv(1024)
    print("收到：", data.decode())
    connection.sendall("你好，我是服务端".encode())
finally:
    connection.close()
    server.close()

客户端

import socket

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
client.connect(("127.0.0.1", 8000))

try:
    client.sendall("你好，我是客户端".encode())
    data = client.recv(1024)
    print("服务端回复：", data.decode())
finally:
    client.close()

先启动服务端，再启动客户端。真实服务端需要循环接受连接，并用线程、进程、事件循环或 I/O 多路复用处理多个客户端。

10. TCP 是字节流，没有消息边界

客户端连续发送 hello 和 world，服务端可能一次读取到 helloworld，也可能分成若干片段。这不是 TCP 出错，而是 TCP 只提供连续、有序的字节流。

应用层需要自己定义消息边界，常见方法包括：

  • 固定长度：每条消息固定占用相同字节数。
  • 分隔符：例如用换行符结束一条消息。
  • 长度前缀：消息头先携带正文长度，再读取指定字节数。
  • 成熟上层协议：使用 HTTP、WebSocket、gRPC 等已经定义好格式的协议。

11. 使用 UDP 进行同机通信

UDP 不需要 listen、accept 和三次握手。接收方绑定地址后，发送方可以直接使用 sendto 发送数据报。

# 服务端
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
server.bind(("127.0.0.1", 8000))
data, address = server.recvfrom(1024)
server.sendto("收到消息".encode(), address)
# 客户端
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
client.sendto("你好".encode(), ("127.0.0.1", 8000))
data, address = client.recvfrom(1024)

13. 端口占用与多进程服务

一般不能让两个无协调的进程同时绑定完全相同的协议、IP 和端口，否则第二个进程通常得到 Address already in use。

但多 Worker 服务可以通过以下方式协作：

  • 多个 Worker 继承主进程创建的监听 Socket。
  • 操作系统提供 SO_REUSEPORT，让多个 Socket 分担新连接。
  • 主进程统一接受连接，再分发给子进程。
  • 不同进程绑定不同 IP，或者一个使用 TCP、另一个使用 UDP。

Gunicorn 常见做法是由主进程管理监听入口和 Worker，而不是让多个 Worker 完全无协调地争抢端口。

14. Unix Domain Socket

如果通信双方确定只在同一台 Linux 或 macOS 机器上，可以使用 Unix Domain Socket。它使用文件系统路径寻址，例如 /tmp/agent-service.sock，不依赖 IP 和端口。

# 服务端
import os
import socket

socket_path = "/tmp/example.sock"
if os.path.exists(socket_path):
    os.remove(socket_path)

server = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
server.bind(socket_path)
server.listen()
connection, _ = server.accept()

try:
    print(connection.recv(1024).decode())
    connection.sendall("服务端已收到".encode())
finally:
    connection.close()
    server.close()
    os.remove(socket_path)

15. 容器中的 localhost 陷阱

Docker 容器通常拥有独立的网络命名空间。因此，“位于同一台物理服务器”不代表共享同一个 127.0.0.1。

容器 A 的 127.0.0.1
≠ 容器 B 的 127.0.0.1
≠ 宿主机的 127.0.0.1

Docker Compose 中，容器间通常通过服务名和容器端口通信，例如 redis:6379、postgres:5432。在 macOS Docker Desktop 中，容器访问宿主机服务时常用 host.docker.internal。实际配置还取决于容器网络模式。

17. Agent 平台中的实际架构

FastAPI Gateway
   ├─ TCP localhost:9000 → Agent Runtime
   ├─ TCP redis:6379     → Redis
   ├─ TCP postgres:5432  → PostgreSQL
   └─ HTTP vllm:8000     → vLLM

Agent Runtime
   └─ Unix Socket / TCP  → Tool Worker

需要区分不同组件的职责：

  • TCP/Unix Socket：提供通信通道。
  • HTTP/RPC：定义请求、响应和序列化协议。
  • 消息队列：提供异步解耦、缓冲、确认和重试。
  • 数据库：保存可恢复的持久化业务状态。
  • WebSocket：连接服务器与浏览器，提供双向实时通信。

Socket 本身不会自动提供消息持久化、消费确认、失败重试、幂等、权限控制和服务发现，这些必须由应用层协议或中间件补齐。

18. 常见问题与排查方法

  • Connection refused：通常说明目标地址可达，但对应端口没有服务监听，或被主动拒绝。
  • Address already in use：目标地址和端口已被占用，或旧连接状态与配置产生冲突。
  • 连接一直超时：检查地址、网络命名空间、防火墙、服务阻塞和连接队列。
  • localhost 能访问，局域网不能：服务可能只绑定了 127.0.0.1。
  • 宿主机能访问，容器不能：容器中的 localhost 指向容器自己。
  • recv 得到半条消息：TCP 没有消息边界，应用协议必须做组包。

常用排查工具包括 ss、lsof、nc、curl 和 tcpdump。排查时依次确认：服务是否监听、绑定在哪个地址、客户端连接哪个地址、端口是否一致、是否处于同一网络命名空间。

19. 面试回答模板

同一台计算机上的不同进程可以通过 Socket 和 Loopback 回环接口通信。服务端创建 Socket，绑定 127.0.0.1 与端口，然后调用 listen 和 accept；客户端创建 Socket 并调用 connect。

数据从客户端用户态写入内核的 Socket 发送缓冲区，经过 TCP/IP 协议栈和 Loopback，再进入服务端 Socket 的接收缓冲区，服务端通过 recv 读取。这个过程通常不经过物理网卡。内核根据源 IP、源端口、目标 IP 和目标端口组成的四元组区分 TCP 连接。

如果通信只发生在本机，也可以使用 Unix Domain Socket，它通过路径寻址并可结合文件权限；如果以后可能扩展到跨机器通信，则 TCP Socket 更通用。

20. 一句话总结

同机进程通过网络通信时，不是两个进程直接交换内存，而是双方各持有一个 Socket，由操作系统内核通过 TCP/UDP 协议栈和 Loopback 完成数据传递。
