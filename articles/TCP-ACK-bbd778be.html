TCP ACK：确认号、累计确认与快速重传

1. ACK 是什么

ACK 是 Acknowledgment 的缩写，是 TCP 的确认机制。它告诉发送方：接收方已经连续收到哪些字节，下一次希望从哪个序列号继续发送。

ack=N 的准确含义不是“收到第 N 个字节”，而是“序号小于 N 的字节已经连续收到，下一次期望收到序号 N”。

2. ACK 标志位与确认号

TCP 首部中有 ACK 标志位和 Acknowledgment Number。ACK=1 表示确认号字段有效；连接建立后，大多数 TCP 报文的 ACK 标志位都会为 1。

3. 按字节确认

若发送方发送 seq=100、长度 50 字节的数据，这段数据占用序号 100～149。接收方正确收到后返回 ack=150，表示下一次希望收到 150。

发送方 → seq=100，len=50 → 接收方
发送方 ← ACK，ack=150    ← 接收方

4. ACK 为什么能实现可靠传输

发送方发送数据后，会把尚未确认的数据暂存在发送缓冲区。收到 ACK 后才能清理相应数据并移动发送窗口；若长期收不到 ACK，就可能触发超时重传。

  • 确认已到达数据
  • 释放发送缓冲区
  • 推进滑动窗口
  • 帮助发现丢包
  • 触发超时重传或快速重传

5. 累计确认

TCP 通常采用累计确认。若连续收到序号 100～399 的字节，只需返回 ack=400，就能确认此前所有连续字节。

6. 中间丢包与重复 ACK

若 100～199 到达、200～299 丢失、300～399 到达，接收方仍然返回 ack=200。因为确认号不能越过连续字节流中的缺口。后续乱序报文到达时，接收方可能再次发送相同确认号，这就是重复 ACK。

seq=100，len=100 → 到达 → ack=200
seq=200，len=100 → 丢失
seq=300，len=100 → 到达 → 重复 ack=200
seq=400，len=100 → 到达 → 重复 ack=200

7. 快速重传

发送方收到多个重复 ACK 时，可以推断某个序号开始的数据可能丢失，而后续数据仍在到达。于是可以在重传计时器超时前重传缺失数据，这就是快速重传。具体触发与拥塞控制算法、SACK 等机制有关。

8. 三次握手中的 ACK

客户端 → SYN，seq=x
服务端 → SYN+ACK，seq=y，ack=x+1
客户端 → ACK，ack=y+1

SYN 会占用一个序列号，所以确认 SYN 时需要加 1。三次握手借助 ACK 确认双方初始序列号和双向收发能力。

9. 四次挥手中的 ACK

主动方 → FIN，seq=u
被动方 → ACK，ack=u+1

FIN 也占用一个序列号。收到 FIN 后回复 ACK，只表示“已经收到你关闭发送方向的请求”，不表示本方也已经发送完数据。

10. ACK 不等于业务成功

TCP ACK 只证明数据已经到达对方 TCP 接收缓冲区，不保证对方应用已经调用 recv()、解析请求、写入数据库或提交业务事务。

11. 纯 ACK 是否占用序列号

纯 ACK 通常不消耗新的序列号；SYN 和 FIN 各占用一个序列号，应用数据按照字节数量占用序列号。若 ACK 报文同时携带数据，数据部分仍然推进发送序列号。

12. 捎带确认与延迟 ACK

TCP 是全双工的。接收方可以把确认信息与反向业务数据放在同一个报文中，这叫捎带确认。接收方也可能短暂延迟 ACK，以便一次确认多段数据或等待与响应数据合并，但不能无限等待。

13. 常见误区

  • ack=100 表示收到字节 100：错误，它表示下一次期望 100。
  • 一个数据段对应一个 ACK：错误，TCP 可以累计确认和延迟确认。
  • 收到 ACK 就表示订单创建成功：错误，只表示到达 TCP 协议栈。
  • ACK 永远单独发送：错误，它可以与反向数据一起发送。

14. 面试回答

ACK 是 TCP 的确认机制。ACK 标志位表示确认号有效，确认号表示接收方下一次期望收到的字节序号。例如发送方发送 seq=100、长度 50 字节的数据，接收方返回 ack=150，表示 100～149 已连续收到。TCP 使用累计确认；若中间出现缺口，即使后续数据到达，接收方仍会重复确认缺口位置，发送方可据此进行快速重传。TCP ACK 只说明数据到达对方协议栈，不等于应用或业务处理成功。

15. 一句话总结

ACK 告诉发送方：“这个序号之前的字节我已经连续收到，下一次请从这个序号继续发送。”
