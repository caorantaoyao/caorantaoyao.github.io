UDP：不建立连接也能发送数据

1. UDP 是什么

UDP 是传输层协议，主要解决一台计算机上的进程如何向另一台计算机上的指定进程发送一条数据。它的全称是 User Datagram Protocol，即用户数据报协议。

TCP 是“先建立连接，再可靠传输字节流”；UDP 是“知道目标 IP 和端口后，直接发送一条数据报”。

2. UDP 在网络分层中的位置

应用层：DNS、音视频、游戏、QUIC

IP 地址负责定位目标计算机，端口负责定位目标计算机上的网络进程，UDP 负责把应用生成的一条消息交给目标端口，底层网络负责实际传输。

3. 一条 UDP 数据如何发送

假设应用希望把 hello 发送到 192.168.1.20:9000：

  1. 应用调用 Socket 接口并指定目标 IP、目标端口和数据。
  2. UDP 加入源端口、目标端口等首部信息。
  3. IP 层加入源 IP 和目标 IP。
  4. 数据包通过底层网络传输。
  5. 接收方内核根据目标端口找到对应 UDP Socket。
  6. 监听该 Socket 的进程读取完整数据报。
应用消息
→ UDP 数据报
→ IP 数据包
→ 网络传输
→ 接收方 UDP Socket
→ 接收进程

4. “无连接”是什么意思

UDP 无连接不是“不使用网络”，而是发送前不需要像 TCP 那样建立并维护一条连接状态。它没有三次握手，也不需要服务端调用 listen() 和 accept()。

TCP：建立连接 → 发送数据 → 关闭连接
UDP：指定目标 IP 和端口 → 直接发送

发送方通常无法仅凭一次发送确定目标进程是否存在、对方是否收到或是否已经处理。

5. UDP 面向数据报

UDP 保留应用消息边界。应用连续发送 hello 和 world，接收方看到的是两条独立数据报，而不是 TCP 那样的连续字节流。

但接收缓冲区必须足够容纳数据报；应用也不应无节制发送超大数据报，因为底层分片和丢包风险会增加。

6. UDP 不提供哪些保证

  • 不保证到达：网络拥塞或设备异常时，数据报可能丢失。
  • 不保证顺序：先发送的数据可能后到。
  • 不保证只到达一次：应用应在需要时使用消息 ID 去重。
  • 不自动重传：基础 UDP 不会因未收到确认而重发。
  • 不提供 TCP 式流量控制：不会自动判断接收方处理能力。
  • 不提供 TCP 式拥塞控制：应用或上层协议需要控制发送速率。

这些是 UDP 不主动提供的能力，而不是说使用 UDP 的上层系统永远无法实现这些能力。

7. 为什么仍然需要 UDP

有些业务更看重实时性和自主控制，而不是让传输层自动保证每一条旧数据最终到达。例如实时视频中某一帧丢失后，等待旧帧重传可能导致后续画面整体卡顿；在线游戏中，最新位置通常比一秒前的位置更有价值。

UDP 的价值主要在于：

  • 无需建立 TCP 连接
  • 协议控制相对简单
  • 保留消息边界
  • 应用可以自行决定怎样处理丢包
  • 支持广播和组播

因此不能简单说“UDP 一定比 TCP 快”，实际性能仍取决于网络、数据规模和上层实现。

选择协议时应问：业务是否需要 TCP 提供的连接、可靠字节流和顺序保证？如果业务有特殊实时要求，或者上层协议准备自行实现相关机制，就可能选择 UDP。

10. Python UDP 示例

接收方

import socket

server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
server.bind(("127.0.0.1", 9000))

data, sender = server.recvfrom(1024)
print("发送方：", sender)
print("内容：", data.decode())

发送方

import socket

client = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
client.sendto(
    "hello".encode(),
    ("127.0.0.1", 9000),
)

UDP 使用 SOCK_DGRAM，TCP 使用 SOCK_STREAM。UDP 接收方绑定端口后直接使用 recvfrom() 接收，不需要 listen() 和 accept()。

11. UDP 中的客户端与服务端

UDP 没有 TCP 式连接，因此客户端和服务端更多是应用角色。服务端通常固定绑定某个端口等待数据，客户端使用临时端口向它发送；双方都可以发送和接收数据报。

DNS 客户端临时端口
→ UDP 53：DNS 查询
→ DNS 服务器
→ 返回客户端临时端口

这个过程不代表双方建立了一条持续存在的连接。

12. 上层可以补充可靠性

如果业务需要，应用可以在 UDP 之上增加消息编号、ACK、超时重传、去重、排序、速率控制和拥塞控制。QUIC 就是重要例子，它基于 UDP，但自行提供可靠传输、TLS 加密、多路复用和丢包恢复。

因此，“使用 UDP”只表示没有使用 TCP 的传输机制，不表示整个应用协议必然不可靠。

13. 常见误区

  • UDP 完全不会丢包：错误，协议不作到达保证。
  • UDP 一定比 TCP 快：错误，真实表现取决于业务和实现。
  • UDP 不能可靠：错误，上层可以自行实现可靠性。
  • UDP 不需要端口：错误，它仍依靠端口找到目标进程。
  • 无连接等于没有 Socket：错误，UDP 同样通过 Socket API 通信。

14. 面试回答

UDP 是传输层的无连接、面向数据报协议。发送方知道目标 IP 和端口后即可发送，不需要 TCP 的三次握手和四次挥手。UDP 保留消息边界，但本身不保证数据一定到达、按顺序到达或只到达一次，也不提供 TCP 式的自动重传、流量控制和拥塞控制。

UDP 协议控制较少，应用能够自行决定如何处理丢包，因此常用于 DNS、实时音视频、在线游戏，并作为 QUIC 的底层承载。使用 UDP 不代表上层应用一定不可靠，上层协议可以自行实现确认、重传和拥塞控制。

15. 一句话总结

UDP 让进程知道目标 IP 和端口后直接发送一条数据报，但是否到达、是否有序以及是否重传，需要由应用自己决定。
